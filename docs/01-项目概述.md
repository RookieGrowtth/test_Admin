# 项目概述

AI-TestHub 面向测试团队，将“用例创建 → 计划执行 → 缺陷提交 → 报告生成”串成可审计闭环，并将 AI 模型接入收敛为一次 API Key 配置。

## 架构决策

本 MVP 不直接复制 MeterSphere 的源码。MeterSphere 是成熟的一站式持续测试平台，适合复杂企业场景；本项目采用零依赖 Node.js 服务和静态管理界面，优先满足轻量、可启动、可演示和可二次开发的目标。核心概念与分层设计仍对齐其项目协作与测试全流程思路。

```text
浏览器管理后台
       │ HTTPS / JSON
AI-TestHub 单服务
 ├─ JWT 会话与 RBAC
 ├─ 项目 / 用例 / 计划 / 执行 / 缺陷
 ├─ 报告聚合与 HTML 导出
 ├─ TOTP 双因素认证
 ├─ AI 兼容接口代理
 └─ JSON 持久化数据卷
       │
OpenAI / DeepSeek / 通义千问等兼容 API
```

## 能力边界

当前版本支持手工测试管理闭环和 AI 辅助。接口自动化、Playwright 执行器、附件二进制存储、邮件及定时任务属于下一阶段扩展项；可在服务端以任务队列和对象存储的方式接入，避免把不受控脚本直接运行在 Web 进程中。

## UI 自动化模块

“UI 自动化”使用 Playwright 脚本资产模型，提供项目归属、环境、浏览器、标签、脚本编辑与执行记录。当前 Web 服务只提交任务到受控执行队列，**不会在 Web 进程直接执行用户提交的任意脚本**。生产接入应使用隔离的 Runner 容器/虚拟机，并限制网络、浏览器权限、测试账号和密钥访问范围。

## 可扩展接口架构

- **兼容层**：`/api/*` 保持管理后台兼容。
- **稳定集成层**：`/api/v1/*` 用于 CI、测试 Runner、报表平台和第三方系统，提供分页、过滤、固定错误模型与 OpenAPI 合约。
- **存储边界**：`backend/storage/sqlite-state.js` 集中处理 SQLite 状态；后续换成规范化表结构或 PostgreSQL 时，路由和 API 契约无需改变。
- **契约边界**：`backend/contracts/openapi.yaml` 是对外接口的机器可读定义，可用于生成客户端、Mock、API 测试和 Runner SDK。
- **执行边界**：Runner 使用受项目范围限制的 `write` Token 上报结果，不与 Web 进程共享脚本执行权限。
